# 2026-11-03 개선 5가지 — 과정과 결과

사용자 요청(스크린숏 3장: 폰 캘린더 11/19 선택, PC 캘린더 11/4·11/3 선택):

- 폰 ① 시간표 수업 일정을 DREAM 알림에서 빼기 ② 캘린더에서 19일을 누르고 오른쪽 아래 + → 오늘(3일)로 들어감, 19일로 ③ 시간 지정 일정에 늦게 들어가면
  소리와 함께 읽어 주는데, 선택으로 — 소리 / 진동 / 무음(화면만 깜빡임), PC 와 같이
- PC: 일정 개수가 다른 날을 고르면 화면이 살짝씩 움직임
- 둘 다: 일정을 등록할 때 사진도(예: 택배 갖고 오기), 일정을 누르면 사진이 먼저

## 1. 브리핑에서 시간표 빼기
- 10/31(8절 39)에 아침 브리핑에 시간표 수업을 넣었던 것을 다시 뺌. 서버 `send-due-notifications/briefing.ts`(habits 조회·`timetableToday` 삭제), 앱 `src/lib/briefing.ts`.
- 시간표는 원래 일정(tasks)을 만들지 않아 다른 알림(정각·미시작)에는 없음 — 브리핑만 손봄. send-due-notifications **v8** 배포, 크론 200.

## 2. 캘린더 + 버튼
- 원인: 아래 + (`Shell.tsx` addNew)는 늘 "지금"으로 새 일정을 엶. 고른 날은 `CalendarTab` 안에만 있었음.
- `CalendarTab` 이 고른 날을 `calendarPick.day` 에 적어 두고(탭을 떠나면 null), + 가 캘린더 탭이면 그날 09:00 으로. 오늘을 골랐으면 예전처럼 다음 15분.
- 화면 시험: 19일 → + → 새 일정 2026-11-19 09:00, '오늘' → 2026-11-03.

## 3. 알람 방식(소리 / 진동 / 무음)
- 설정에 `alarmMode`(계정 설정 profiles.settings 에 들어가 PC·폰 같이). 기본 "sound" = 예전과 똑같음.
- `alarmOutput()`(lib/settings.ts) 이 무엇을 낼지 정함: 소리면 소리 + (켜 두었으면) 읽어 주기 + 진동, 진동이면 진동 + 화면 깜빡임(패턴이 '없음'이면 기본 패턴),
  무음이면 화면 깜빡임만.
- 적용한 곳: `ReminderEngine` fire(곧 시작·끝날 시간 소리, 정각·미시작 진동·읽어 주기, 앱이 띄우는 시스템 알림 — 무음이면 silent),
  `AlarmOverlay`(소리 안 냄 + `ScreenFlash`, '소리만 끄기' 숨김), `OverdueSiren`(소리 대신 6초 깜빡이고 끝), 경고창 '경고음 끄기' 숨김.
- 깜빡임: 화면 가장자리 1.1초 간격(번쩍이지 않게, 움직임 줄이기 설정이면 2.4초). 가장 밝을 때 스크린숏으로 확인.
- 앱을 닫았을 때 오는 서버 푸시는 바꾸지 않음 — 폰 설정을 따름(설정 화면 설명에 적음). 무음 알림은 갤럭시 잠금화면에서 숨겨질 수 있어서.
- 시험: 단위 4(기본·진동·무음·저장값 거르기). 화면: 소리 모드 — 소리 시작 17번·읽어 주기 1번·'소리만 끄기' 있음 / 무음 — 소리 0·읽어 주기 0·깜빡임 있음·버튼 없음.
  (시험은 음량 0. 녹음 소리는 `AudioBufferSourceNode.start`, 합성음은 `AudioScheduledSourceNode.start` 라 둘 다 세야 함 — 처음엔 하나만 세서 0 으로 보였음.)

## 4. PC 화면 밀림
- 원인: 문서 전체가 스크롤 — 일정이 많은 날은 스크롤바가 생기고 적은 날은 없어져 내용 폭이 스크롤바만큼(시험 창에선 10px) 바뀜.
- `html { scrollbar-gutter: stable }` — 스크롤바 자리를 늘 남겨 둠(창을 열어 스크롤을 막을 때도 안 밀림).
- 시험(헤드리스는 기본으로 스크롤바를 숨겨서 `--hide-scrollbars` 를 빼고): 1400×1000, 4일(20개, 문서 2055px)↔3일(1개, 1000px) —
  고친 뒤 월 제목 오른쪽 1270↔1270, 고정을 끄면 1270↔1280(밀림을 시험이 잡음). `clientWidth` 숫자는 둘 다 바뀌어 눈에 보이는 위치로 봄.

## 5. 일정 사진
- 저장: 드라이브 재사용 — 줄여서(`shrinkPhoto`, 긴 변 1568px JPEG) '일정 사진' 폴더에 올림(용량 150MB 를 같이 씀, 서버가 크기 확인). 일정엔 `photo_id` 만.
  동기화는 일정 줄 그대로(사진 있는 일정만 칸을 보냄). 한 번 받은 사진은 Cache Storage `must-task-photos` — 다음엔 바로·오프라인에서도.
- 화면: 일정 창 별표 옆 '사진'(로그인 필요) → 올리는 중 % → 맨 위에 크게, 바꾸기·빼기. 누르면 화면 가득(body 로 portal). 목록 제목 옆 카메라.
  일정을 열면 사진이 제목 위에 먼저 보임.
- 치우기: 붙였다가 취소·다른 사진으로 바꿈·뺌·일정 삭제 → 드라이브에서도 지움. 반복(습관)은 사진 없음.
- DB `20261103000000_task_photo`(MCP 로 적용): `tasks.photo_id uuid` + 내 드라이브 파일만 붙게(남의 것·없는 것은 비움, 바뀔 때만 확인) +
  드라이브에서 지우면 일정의 photo_id 를 비우고 updated_at 을 올림(다른 기기도 받아 감). 시험 7개 통과. 라이브에서 칸·트리거 2개 확인.
- 화면 시험(가짜 Supabase): 사진 고르기 → 드라이브 '일정 사진'에 '택배 갖고 오기 사진.jpg'(JPEG) → 저장하면 일정에 photo_id → 목록 카메라 →
  열면 사진이 제목보다 위 → 크게 보기·닫기 → 다른 일정에 붙였다가 취소하면 표 줄·파일 둘 다 지움, 저장한 사진은 그대로.
